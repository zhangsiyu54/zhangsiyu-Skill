# Pitfalls

Check this list before finalizing conclusions. Each entry: Trigger (when it happens), Mechanism (why it happens), Symptom (how it shows up in output), Fix (what to do instead).

## 1. TMB computed without normalizing to callable panel size

- **Trigger:** Tumor mutation burden is reported as a mutation count or as mutations/Mb using the wrong denominator, or WES-derived and targeted-panel-derived TMB values are compared or pooled directly.
- **Mechanism:** TMB is mutations divided by the number of megabases actually callable at adequate depth in that assay, not the nominal genome or exome size. Targeted panels (0.5-2 Mb) systematically enrich for hotspot/driver-dense regions, so their raw mutations/Mb is not on the same scale as WES (~30-38 Mb coding) or WGS. Even within "WES," different capture kits and coverage thresholds change the callable footprint by 10-20%.
- **Symptom:** TMB values that look implausibly high or low relative to published cohort ranges for that tumor type; panel-derived TMB compared directly against WES-based clinical cutoffs (e.g. the 10 mut/Mb pembrolizumab threshold, which was calibrated on FoundationOne CDx, not WES); TMB distributions that shift abruptly at a cohort boundary corresponding to a change in sequencing platform.
- **Fix:** Always report and use the assay-specific callable/interrogated size as denominator (from the panel BED file or exome capture manifest, not "whole exome = 30 Mb" as a universal constant). State the assay and denominator explicitly in methods. Never compare or merge TMB across platforms without harmonization (e.g. Friends of Cancer Research TMB Harmonization Project approach) or without at minimum flagging the platforms as separate groups in any statistical comparison.

## 2. Signature deconvolution with too few mutations per sample

- **Trigger:** Fitting or extracting mutational signatures on samples with roughly fewer than 50-100 SNVs (exact threshold depends on signature similarity and panel size), especially common with targeted-panel data or hypomutated tumor types (e.g. pediatric tumors, some sarcomas).
- **Mechanism:** Signature fitting is a constrained regression/NMF problem over a 96-channel (or 83-channel indel) mutation spectrum; with few mutations the empirical spectrum is dominated by sampling noise, so the optimizer can assign non-zero exposure to signatures that are mathematically convenient rather than biologically present. Confidence intervals on exposures widen enormously as mutation count drops.
- **Symptom:** Signature exposure plots showing many signatures at low-to-moderate contribution per sample, inconsistent signature calls for technical replicates or similar samples, "noisy" activity in signatures that are biologically implausible for the tissue (e.g. SBS7 UV signature in a non-skin/non-uveal tumor), or dramatic changes in the top signature when one or two mutations are added/removed.
- **Fix:** Set and report a minimum mutation-count threshold per sample before running signature analysis (commonly >=50, ideally >=100 SNVs for stable single-sample fitting); below threshold, either exclude the sample from signature analysis, aggregate across the cohort/subtype before extraction, or report exposures explicitly labeled as "low-confidence/unstable." Prefer cohort-level de novo extraction over single-sample fitting when most samples are low-mutation. Report bootstrap or cosine-similarity-based confidence rather than a single point estimate.

## 3. Conflating signature refitting with de novo extraction

- **Trigger:** Using a "refit to reference signatures" workflow (e.g. deconstructSigs, or SigProfilerAssignment/mSigAct fitting against COSMIC SBS reference set) but describing or interpreting the result as if novel signatures had been discovered, or vice versa running de novo extraction on too small a cohort and treating results as validated reference signatures.
- **Mechanism:** Refitting solves a constrained regression against a fixed, predefined signature basis (e.g. all 60+ COSMIC SBS signatures), so it can only output combinations of what's already in the reference set - it will force-fit the closest available combination even if the true underlying process is not represented in the reference, spreading its activity across several imperfectly-matching reference signatures. De novo extraction (NMF-based, e.g. SigProfilerExtractor) instead estimates signatures directly from the cohort's mutation matrix and can reveal genuinely novel or cohort-specific processes, but requires many samples (commonly cited practical minimum ~20-50+ samples with sufficient mutations each) and rank-selection stability testing to be trustworthy.
- **Symptom:** Refitting output "explains" 100% of mutations across an implausibly large number of signatures with small overlapping contributions (multicollinearity between similar reference signatures, e.g. SBS5 vs SBS40 flat signatures, or SBS2 vs SBS13 APOBEC signatures); or a de novo extraction on <20 samples claiming a "novel" signature that is really cohort-specific noise or an artifact signature.
- **Fix:** Explicitly state whether the workflow is refitting (bounded by reference signature set - cannot discover new biology, but is appropriate for small/single-sample data) or de novo extraction (can discover novel processes but needs a reasonably sized cohort and rank stability/silhouette assessment across multiple NMF runs). Do not present refitting results as evidence of "no other processes present" - absence of an unlisted signature in a refitting result is not evidence of its absence, only evidence it wasn't in the reference basis offered.

## 4. Interpreting CNV calls without purity/ploidy correction

- **Trigger:** Reporting gene-level amplification/deletion status directly from raw log2 copy-ratio or segment-mean values in samples with low tumor purity (roughly <30-40%) or non-diploid (whole-genome-doubled) background, without applying a purity/ploidy-aware model.
- **Mechanism:** Observed copy ratio is a mixture of tumor and normal signal weighted by purity; in a 20% purity sample, a true homozygous deletion appears as only a modest log2 reduction, and a true single-copy gain can look nearly flat. Without algorithms that jointly estimate purity, ploidy, and integer copy number (e.g. ASCAT, ABSOLUTE, FACETS, PureCN, Sequenza), raw log-ratio thresholds systematically under-call events in low-purity samples and over- or under-call in high-ploidy (genome-doubled) tumors where the "neutral" copy number is not 2.
- **Symptom:** Focal deep deletions in known tumor suppressors (e.g. CDKN2A, PTEN) failing to reach the amplitude threshold used for high-purity samples; amplification calls that don't match downstream expression/IHC/FISH validation; systematic differences in CNV burden that track with purity rather than biology across a cohort.
- **Fix:** Estimate purity and ploidy explicitly (from the variant caller, a dedicated tool, or supplied clinical/pathology purity estimate) before calling absolute/integer copy number, and use purity-aware thresholds rather than one fixed log2 cutoff for the whole cohort. Report purity/ploidy per sample alongside CNV results, and flag low-purity samples (e.g. <20-30%) as having reduced sensitivity for focal events.

## 5. Germline variants not filtered out of a "somatic" mutation table

- **Trigger:** Tumor-only sequencing (no matched normal) with variant table treated as fully somatic without a panel-of-normals (PoN) or population database filter, or a "somatic MAF" received from a third party without documentation of germline filtering.
- **Mechanism:** Without a matched normal, standard variant callers cannot distinguish an inherited heterozygous SNP from a true somatic mutation; common germline variants (including in cancer genes like BRCA2, ATM, CHEK2) will appear in the raw call set at population allele frequencies. Filtering against gnomAD/1000 Genomes population allele frequency and/or an in-house panel of normals removes most but not all of these; rare germline variants and population-specific variants not well represented in reference databases can still slip through.
- **Symptom:** Recurrent "somatic" mutations at population-common polymorphism sites, unusually high mutation frequency in genes known mainly for germline predisposition, VAF clustering near 50% or 100% (heterozygous/homozygous germline) rather than the tumor-purity-scaled VAF expected for a true somatic clonal mutation, or the same "somatic" variant recurring across supposedly independent tumors at an implausible rate.
- **Fix:** Confirm and document whether calling was tumor-normal (preferred) or tumor-only. For tumor-only, require and report population-frequency filtering (e.g. gnomAD AF threshold, commonly <0.0001-0.001 depending on cohort ancestry composition) plus panel-of-normals filtering, and flag known predisposition genes for manual review. State this limitation explicitly in methods/limitations text whenever tumor-only data is used.

## 6. Not distinguishing synonymous from non-synonymous mutations in driver-gene frequency

- **Trigger:** Computing "gene X is mutated in Y% of samples" using all variant classifications (including synonymous/silent, intronic, UTR) rather than restricting to functionally relevant classes, or mixing this convention inconsistently across genes/cohorts.
- **Mechanism:** Passenger and synonymous mutations accumulate roughly in proportion to background mutation rate and gene length/replication timing, not selection; including them inflates "mutation frequency" for large genes (e.g. TTN, MUC16) that are mutated often simply because they are enormous, and dilutes true enrichment signal in true driver genes with functional variant filtering.
- **Symptom:** Oncoplots/frequency tables where very large, non-driver genes (TTN, MUC16, OBSCN) appear near the top of the mutation frequency ranking; frequency percentages that don't match published driver-gene frequencies for the same cancer type in maftools/TCGA/COSMIC references.
- **Fix:** Default to non-synonymous/functional classifications (missense, nonsense, frameshift/inframe indel, splice site) for driver-gene frequency and oncoplot summaries, explicitly excluding silent/synonymous and typically intronic/UTR variants unless the analysis is specifically about background mutation rate. State the exact variant classification set used in methods, and consider excluding known non-driver "long gene" artifacts from headline driver summaries (or flag them explicitly, e.g. "TTN shown for reference; not a putative driver").

## 7. Co-occurrence/mutual exclusivity claims without proper statistical testing or multiple-testing correction

- **Trigger:** Reporting gene pairs as "co-occurring" or "mutually exclusive" based on visual inspection of an oncoplot, or running many pairwise tests (e.g. all pairs among the top 20-30 genes, ~200-400 tests) and reporting nominal p-values without correction.
- **Mechanism:** With dozens of genes tested pairwise, the number of comparisons grows combinatorially (n choose 2), so at alpha=0.05 several "significant" pairs are expected by chance alone even with no true biological relationship. Fisher's exact test on sparse contingency tables (common when gene frequencies are low) is also sensitive to small sample sizes and can produce unstable p-values.
- **Symptom:** Long lists of "significant" gene pairs from a cohort of a few dozen to a couple hundred samples, especially involving genes with mutation frequency under ~5%, where cell counts in the 2x2 table are single digits; conclusions asserting mutual exclusivity or co-occurrence not replicated in larger published cohorts for the same cancer type.
- **Fix:** Restrict pairwise co-occurrence/exclusivity testing to genes with adequate mutation frequency (commonly >=3-5% or a minimum absolute count, e.g. >=5-10 mutated samples) in the cohort, apply multiple-testing correction (Benjamini-Hochberg FDR, or Bonferroni for a small fixed set of pre-specified hypotheses) across all pairs actually tested, and report effect size/odds ratio with confidence interval alongside the corrected p-value rather than the p-value alone. Treat exploratory (all-pairs) results as hypothesis-generating, not confirmatory.

## 8. Small cohort size producing mutation frequency percentages with false precision

- **Trigger:** Reporting gene mutation frequencies to one or two decimal places (e.g. "17.65%") for cohorts of a few dozen samples, or presenting subgroup frequencies (e.g. within a 12-sample clinical subgroup) with the same apparent precision as a several-hundred-sample cohort.
- **Mechanism:** With n=17 samples, one mutated sample corresponds to ~5.9% - the discrete jump size itself is larger than the decimal precision being reported, and the binomial confidence interval around any such proportion is wide (for n=20, a 20% observed frequency has a ~95% CI roughly spanning 6-44%). Decimal precision implies a level of certainty the sample size cannot support.
- **Symptom:** Frequency tables/oncoplots reporting percentages with decimals for cohorts under ~50-100 samples; subgroup comparisons claiming "gene X is more frequent in group A (25%) vs group B (18%)" when each group has only a handful of mutated samples.
- **Fix:** Round frequency percentages appropriately to cohort size (whole numbers for n<100 is a reasonable default), always report the underlying count alongside the percentage (e.g. "3/17, 18%"), and report a confidence interval (exact/Clopper-Pearson binomial CI) for any frequency being compared across groups or against a published reference cohort. Explicitly flag subgroup analyses with n<20 as underpowered for frequency comparison.

## 9. Inconsistent genome build (hg19 vs hg38) across MAF, CNV, and annotation

- **Trigger:** Mutation calls (MAF), CNV segment/gene calls, and gene annotation/reference signature tracks originate from different pipelines or historical batches and are combined without confirming a shared genome build.
- **Mechanism:** hg19 and hg38 coordinates for the same gene/locus differ (sometimes by megabases for genes near assembly-patched or restructured regions), and gene symbol-to-coordinate mapping files (e.g. GTF/BED used for CNV gene-level calls) are build-specific. Silently combining builds produces coordinate-based joins (e.g. matching a mutation position to a CNV segment, or a gene to a cytoband) that are simply wrong for a subset of loci, without any error being thrown.
- **Symptom:** A subset of genes showing implausible or contradictory mutation+CNV combinations (e.g. a gene "deleted" in the CNV table but also carrying a high-VAF missense mutation in the same sample, which is possible but should be rare and warrants a build check); position-based lollipop/domain mapping placing mutations outside the known protein-coding region; liftover-related duplicate or missing loci.
- **Fix:** Confirm and record genome build for every input table before joining (MAF header/comments, CNV caller config, annotation source), and if builds differ, perform an explicit, versioned liftover (e.g. UCSC liftOver or CrossMap) with the mapping documented in methods rather than assuming coordinate compatibility. Reject or flag any cross-build join at the harmonization/QC step per `references/cns-method-guide.md`.

## 10. Signature attribution treated as clinically actionable without validated signature-therapy matching

- **Trigger:** A COSMIC signature exposure result (e.g. dominant SBS3, "HRD-associated," or SBS4, "tobacco-associated") is directly translated into a treatment recommendation (e.g. "give a PARP inhibitor") without going through a validated, assay-matched HRD/biomarker test.
- **Mechanism:** SBS3 (and related indel signature ID6/HRD-associated signatures) correlates with homologous recombination deficiency at a population level, but single-sample signature exposure from limited mutation counts (especially from panel data or low-purity samples, see Pitfalls #2 and #4) has meaningful false-positive and false-negative rates; clinically validated HRD tests (e.g. genomic scar scores, myChoice HRD, or confirmed BRCA1/2 biallelic inactivation) use specific validated algorithms and thresholds that are not the same computation as a general-purpose COSMIC SBS3 exposure fraction.
- **Symptom:** Report language stating a specific drug or trial eligibility is supported "because signature SBS3 was detected," without reference to an FDA/EMA-cleared or clinically validated companion diagnostic, and without acknowledging sample-level confidence in the signature call.
- **Fix:** Present signature findings as research/exploratory unless the pipeline reproduces a specific validated clinical assay's exact method and thresholds. Explicitly state in the report/limitations that signature exposure is not a substitute for a validated companion diagnostic, and that any therapeutic hypothesis generated from signature data should be confirmed with the appropriate clinical-grade test before acting on it.

## 11. FFPE and sequencing artifact signatures mistaken for genuine mutational processes

- **Trigger:** Signature analysis run on FFPE-derived DNA, low-input, or amplicon/hybrid-capture library prep data without screening for known artifact signatures.
- **Mechanism:** FFPE fixation causes cytosine deamination artifacts that mimic a C>T signature (historically overlapping with, and now separated from, SBS1/aging signatures as dedicated FFPE-artifact signatures in recent COSMIC releases, e.g. SBS-FFPE-like/artifact categories); oxidative DNA damage during library prep produces 8-oxoguanine-driven G>T/C>A artifacts (historically flagged as signature-like "SBS18-adjacent" oxidative artifact patterns). These are technical, not biological, signals.
- **Symptom:** Unexpectedly high and fairly uniform contribution of a C>T-dominated or G>T-dominated signature across an entire FFPE-derived cohort regardless of clinical subgroup, inconsistent with known biology of the tumor type; signature profile changes when the same sample is re-sequenced from fresh-frozen material.
- **Fix:** Record specimen type (FFPE vs fresh-frozen/blood) for every sample and flag FFPE-derived samples for artifact-aware signature analysis (use the COSMIC reference set that includes recognized artifact signatures, and/or apply an FFPE deamination filter before signature fitting). Do not report an FFPE-consistent artifact signature as a biological mutational process without corroborating evidence.

## 12. Focal vs arm-level/broad CNV events not distinguished

- **Trigger:** A single amplitude threshold (e.g. "log2 ratio > 0.3 = gain") is applied uniformly to call CNV "events," without separating focal (gene/small-region-scale) alterations from arm-level or whole-chromosome events.
- **Mechanism:** Broad, arm-level gains/losses (common in aneuploid tumors) and focal high-level amplifications/homozygous deletions (more often reflecting targeted selection on a specific gene, e.g. MYC or ERBB2 focal amplification vs whole-chromosome-8q gain) have different biological implications and different appropriate calling logic (segment size and amplitude both matter); collapsing them into one "gain/loss" category loses this distinction and can make a passenger arm-level gain look equivalent to a driver-level focal amplification.
- **Symptom:** CNV heatmap showing an entire chromosome arm as "amplified" for a gene of interest with no way to tell whether that gene is riding a broad event or is the focal target; oncoprint-style CNV summaries that overstate "amplification frequency" for genes that are simply located on a commonly arm-gained chromosome (e.g. 8q, 20q).
- **Fix:** Report focal and broad/arm-level events separately (e.g. GISTIC2-style focal vs broad q-value/amplitude outputs, or a segment-length threshold to distinguish focal from arm-scale calls), and when highlighting a specific gene's amplification, note whether it sits within a focal peak or a broad arm event.

## 13. Clonal vs subclonal status ignored in mutation burden and signature analysis

- **Trigger:** TMB and signature exposures computed from all called variants regardless of variant allele frequency (VAF)/cancer cell fraction (CCF), mixing high-confidence clonal mutations with low-VAF subclonal calls that may include sequencing noise, especially in samples with heterogeneous purity or multi-region sampling.
- **Mechanism:** Subclonal mutations by definition have lower VAF (scaled by both purity and the subclone's cellular fraction), pushing them closer to the detection/noise floor where false positives are more likely, and different callers/filters handle low-VAF calls inconsistently; including or excluding them shifts TMB and signature spectra in ways that are technical (caller sensitivity) rather than purely biological.
- **Symptom:** TMB or signature results that shift substantially when a variant caller's VAF/depth filter is changed slightly; discordant TMB between two sequencing runs of the same sample at different depth; a sample-level dominant signature that changes when restricting to high-VAF (clonal) mutations only.
- **Fix:** Report the VAF/depth filtering thresholds used for variant inclusion explicitly, and where feasible, report both an "all mutations" and a "clonal-only" (high-VAF/CCF-estimated-clonal) TMB and signature summary, especially for multi-region or serial-sampling designs. Flag TMB/signature comparisons across samples with very different purity or sequencing depth as requiring subclonal-aware normalization.

## 14. Outdated or mixed COSMIC signature reference versions used within one analysis

- **Trigger:** Combining or comparing signature results generated against the legacy COSMIC v2 (~30 signatures, "Signature 1, 2, 3...") reference with results generated against COSMIC v3.x (SBS1, SBS2, ... 65+ signatures, plus separate DBS/ID signature classes), or not stating which version was used.
- **Mechanism:** COSMIC v3 reorganized and expanded the signature catalogue with a different mutation-type resolution and decomposition (splitting some legacy signatures into several more specific ones, adding artifact and rare signatures); a v2 "Signature 3" (HRD) and a v3 "SBS3" are related but not numerically identical in composition, and exposure fractions are not directly comparable across versions.
- **Symptom:** A report citing "Signature 6" in one section and "SBS6" in another as if interchangeable; exposure percentages that don't reconcile when a cohort is reanalyzed with an updated tool version; literature comparisons that silently mix v2- and v3-based published frequencies.
- **Fix:** Always state the exact COSMIC/reference signature catalogue version (and tool + version, e.g. SigProfilerExtractor vX.X against COSMIC v3.4 GRCh38) in methods, and avoid direct numeric comparison of exposures computed against different reference versions. When reconciling with older literature that used v2 signature numbers, treat the mapping to v3 SBS signatures as approximate, not identity.
