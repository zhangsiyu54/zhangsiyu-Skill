# Common Pitfalls and Failure Modes

Read this file before finalizing any single-cell conclusion. Each entry gives the concrete trigger condition, the mechanism that produces the error, the symptom an agent or reviewer would observe, and the fix. Treat this as a pre-submission checklist, not background reading.

## 1. Regressing out the biological variable of interest as a "technical" covariate

- **Trigger:** `ScaleData(vars.to.regress = ...)` or `sc.pp.regress_out(...)` includes a variable that is confounded with the experimental question (e.g., regressing out "cell cycle score" in a proliferation study, or regressing out "sample" when sample IS condition).
- **Mechanism:** Linear regression of a covariate that correlates with the biology of interest removes real signal along with (or instead of) the intended technical noise. If condition and covariate are confounded (e.g., all treated samples were processed in one batch), regressing "batch" also erases the treatment effect.
- **Symptom:** Real biological subpopulations or DE signal disappear after regression; UMAP looks unexpectedly homogeneous; effect sizes shrink to near zero in a comparison that has strong prior literature support.
- **Fix:** Regress only variables that are (a) demonstrably technical (e.g., percent.mt, sequencing depth) and (b) not collinear with the design variable. Check the covariate-vs-condition contingency/correlation before regressing. When cell cycle is a real biological driver of the question (e.g., stem cell studies), do not remove it blindly — consider `CellCycleScoring` difference-based regression only when cycling is a nuisance, and state the decision explicitly in methods.

## 2. Pseudoreplication: cell-level tests treated as if they had sample-level replication

- **Trigger:** Running `FindMarkers`/Wilcoxon/MAST/t-test on cells pooled across samples to compare condition A vs B within a cell type, then reporting p-values as if n = number of cells.
- **Mechanism:** Cells from the same biological sample are not independent observations (they share genetic background, batch, and technical processing). Cell-level tests treat thousands of non-independent cells as independent samples, collapsing biological variance and mistaking it for statistical power. This inflates false discovery rates dramatically — Squair et al. (Nat Commun 2021) showed widely-used cell-level DE methods can call hundreds of "significant" genes between two random splits of the same biological samples.
- **Symptom:** Extremely small p-values (often 1e-50 or smaller) for condition effects that are not visually obvious in violin/dot plots; DE gene lists that don't replicate when repeated with a different subsample; a p-value distribution skewed heavily toward zero even at genes with no per-sample consistency.
- **Fix:** For condition-vs-condition (not cluster-vs-cluster) comparisons, aggregate to pseudobulk per sample x cell type and run edgeR/DESeq2/limma-voom with a design that includes condition (Crowell et al., muscat, Nat Commun 2020). If a mixed-model approach is used instead (Zimmerman et al., Nat Commun 2021), include a random effect for individual/sample. Reserve cell-level tests for marker discovery (cluster vs rest, within one sample or when replication is not the goal) and explicitly label them exploratory.

## 3. Doublet detection run after subsetting or filtering (order-of-operations error)

- **Trigger:** Cells are first filtered by QC thresholds or subsetted to a cluster of interest, and doublet scores (DoubletFinder, scDblFinder, Scrublet) are computed afterward, or doublet detection is run once on a merged multi-sample object.
- **Mechanism:** Doublet simulation methods build a per-cell expected doublet rate and simulate synthetic doublets from the *same pool of cells* being scored. If low-quality cells were already removed, the doublet rate estimate and nearest-neighbor density calculations are shifted. Worse, running these tools on a merged multi-sample object mixes cells from different samples into the same neighbor graph, so cross-sample "doublets" that are actually two singlets from different samples get miscalled, or true within-sample doublets get diluted and missed.
- **Symptom:** Doublet fraction wildly inconsistent with the expected loading-based doublet rate (10x targets ~0.4-0.8% per 1,000 cells loaded); doublet calls cluster suspiciously by sample; clusters that are actually doublet-driven (co-expressing two lineage marker sets) are not flagged.
- **Fix:** Run doublet detection per-sample, before merging/integration, and before final QC filtering removes reference structure the algorithm needs (though extreme empty droplets/ambient-only barcodes should already be excluded via cell-calling). Use the expected doublet rate from the loading concentration as the `nExp`/expected-rate parameter, not a fixed default. Re-verify doublet calls after clustering by checking whether flagged cells co-express markers from two otherwise-distinct clusters.

## 4. Ambient RNA contamination misread as a real marker signal

- **Trigger:** A highly abundant, highly expressed gene (e.g., hemoglobin genes in a non-erythroid tissue prep, albumin in liver preps, immunoglobulin genes in lymphoid tissue) shows low-level expression across many unrelated clusters, and it gets used as if it were a specific marker for the cluster where it happens to be highest.
- **Mechanism:** Highly expressed transcripts leak into the "soup" of ambient mRNA present in the cell-free fraction of the droplet emulsion, and every droplet/cell picks up a background level proportional to its RNA content and the ambient concentration. This background scales with a cell's total UMI count, so larger cells (which are often the "positive" cluster) show more contamination even without true expression.
- **Symptom:** A supposed marker gene is "detected" at low-but-nonzero level in nearly every cluster; the "marker" gene is a highly abundant secretory or lineage-restricted transcript in a nearby dominant cell type (hepatocytes, red blood cells, plasma cells); DotPlot shows broad low-level dot without a clean drop-off.
- **Fix:** Run SoupX (Young & Behjati, GigaScience 2020) or DecontX/CellBender ambient-correction before finalizing marker calls, especially in tissues with a dominant high-RNA-content cell type. When ambient correction isn't run, cross-check candidate markers against a panel (see #7) and require a sharp on/off pattern, not just "highest average expression."

## 5. Cluster resolution / number of PCs chosen arbitrarily

- **Trigger:** Using a fixed default (`resolution = 0.8`, `dims = 1:10`) regardless of dataset size, depth, or heterogeneity, without checking an elbow plot, JackStraw p-values, or clustering stability (e.g., clustree) across a resolution sweep.
- **Mechanism:** Too few PCs under-represents biological variance (rare populations collapse into larger neighbors); too many PCs incorporates noise dimensions that fragment clusters or introduce spurious substructure. Resolution interacts with PC count and the actual number of distinct populations, so a default tuned on one paper's 10,000-cell PBMC dataset does not generalize to a 100,000-cell tumor atlas or a 2,000-cell FACS-sorted subset.
- **Symptom:** Clusters that don't survive marker validation (no distinguishing markers between two "different" clusters); a single well-known cell type (e.g., T cells) is arbitrarily split by resolution rather than a documented biological axis; changing resolution by 0.1 causes cluster identities to reorganize substantially, indicating instability.
- **Fix:** Inspect the PCA elbow plot (variance explained per PC) or JackStraw significance and choose a PC cutoff where added PCs stop contributing distinguishable structure. Sweep clustering resolution and check stability (e.g., clustree, silhouette, or marker-support at each resolution) rather than accepting the first result. Report the chosen PCs/resolution and the evidence used to choose them in methods.

## 6. Annotating a cell type from a single marker gene, without absence markers

- **Trigger:** A cluster is labeled based on one gene showing elevated (not necessarily specific) expression, e.g., "this is a Treg cluster because FOXP3 is expressed," without checking canonical co-markers or genes that should be absent.
- **Mechanism:** Many marker genes are not perfectly specific: they are shared across related lineages, subject to ambient contamination (#4), or expressed at low levels due to dropout/technical noise elsewhere. A single positive gene cannot distinguish "true expression, correct identity" from "ambient signal," "doublet," or "related-but-distinct cell state."
- **Symptom:** Confident cell type labels that don't hold up under a second analyst's marker panel; annotation contradicts tissue-appropriate expected cell type composition; canonical negative markers (e.g., CD3 in a "T cell" cluster that also strongly expresses CD19) are never checked.
- **Fix:** Require a panel of >=2-3 canonical positive markers plus at least one expected-absent marker for the candidate identity, consistent with literature for that tissue/species. Cross-reference cluster size, expected tissue composition, and (if available) orthogonal reference mapping (Azimuth/SingleR/CellTypist) as corroboration, not sole evidence. Label ambiguous clusters `needs_annotation` rather than forcing a name.

## 7. UMAP/t-SNE distances misread as quantitative similarity

- **Trigger:** Interpreting UMAP inter-cluster distance, cluster size, or point density as meaningful quantitative statements — e.g., "cluster A is more similar to B than to C because they're closer on the UMAP," or "this population is rare because it looks small on the plot."
- **Mechanism:** UMAP (and t-SNE) preserve local neighbor relationships but explicitly do NOT preserve global distances, cluster sizes, or inter-cluster gaps in a quantitative way; the layout is a stochastic, hyperparameter-sensitive 2D projection of much higher-dimensional structure. Apparent gaps between clusters can be an artifact of the algorithm's repulsion behavior rather than real transcriptional discontinuity, and apparent point density is affected by overplotting, not cell abundance.
- **Symptom:** Claims like "these two clusters are transcriptionally close/far" based only on the 2D plot; trajectory or lineage claims made purely from UMAP adjacency without pseudotime/RNA velocity/lineage tracing support; different UMAP runs (or Seurat vs Scanpy defaults) show different apparent distances for the same clusters.
- **Fix:** Use UMAP only for qualitative visualization of neighbor-graph-based clustering. Support any claim about relatedness with clustering statistics (e.g., shared markers, correlation of pseudobulk profiles, PC-space distance) or explicit trajectory inference tools. Never justify a biological distance/similarity claim by eye from the 2D layout alone.

## 8. Running trajectory/pseudotime on disconnected or unrelated cell populations

- **Trigger:** Applying Slingshot/monocle3/tradeSeq pseudotime across an entire dataset that includes clearly distinct lineages (e.g., immune cells and epithelial cells together), or across a subset that has no plausible continuous differentiation relationship.
- **Mechanism:** Trajectory algorithms fit a minimum spanning tree or principal graph through cell state space and will always produce *some* ordering, regardless of whether a true continuous biological process connects the input cells. There is no built-in check that the input represents a genuine differentiation continuum.
- **Symptom:** A "trajectory" that runs through obviously unrelated terminally differentiated cell types (e.g., a "path" from B cells to fibroblasts); branch points that don't align with any known developmental biology; pseudotime values that only reflect UMAP layout order rather than any validated marker gradient.
- **Fix:** Subset to a biologically justified lineage before running trajectory inference, and pick a root/starting population from independent evidence (progenitor markers, time-course design, or known biology), not just algorithmic root-finding. Validate the inferred trajectory with known stage-specific markers along the pseudotime axis before reporting it, and state explicitly which populations were excluded and why.

## 9. SCTransform vs LogNormalize mismatch when combining datasets or objects

- **Trigger:** Merging or comparing two Seurat objects/assays where one was processed with SCTransform and the other with standard LogNormalize, or mixing outputs (e.g., using SCT `data` slot in a DE test designed for log-normalized counts), or re-running `NormalizeData` on an SCT assay.
- **Mechanism:** SCTransform models counts with a regularized negative binomial regression and produces Pearson residuals, not the same log-normalized scale as `NormalizeData`. Statistical tests, marker thresholds, and module scoring assume a specific input scale; mixing them silently produces meaningless numeric comparisons (e.g., comparing SCT residuals across samples processed with different regression parameters, or running FindMarkers against the wrong assay/slot).
- **Symptom:** Marker fold-changes/log2FC values that look implausibly large or small; DE results that don't reproduce between "equivalent" analyses using different normalization; per-sample bimodal expression jumps at the exact object-merge boundary.
- **Fix:** Use one normalization method consistently within an analysis; when integrating multiple samples with SCTransform, use `PrepSCTFindMarkers` before differential expression, and use `SelectIntegrationFeatures`/`PrepSCTIntegration` for the SCT integration workflow rather than treating merged SCT assays like a plain log-normalized assay. Record which assay/slot (counts/data/scale.data) each downstream step reads from.

## 10. Integration/batch correction over-correcting and removing real biological signal

- **Trigger:** Applying Harmony/Seurat CCA-RPCA/scVI integration across samples where biological condition is confounded with (or perfectly collinear with) batch/sample identity — e.g., all "treated" samples were run as one batch and all "control" samples as another.
- **Mechanism:** Batch correction methods are designed to align shared cell states across the correction variable. If the correction variable is confounded with the biological variable of interest, the algorithm cannot distinguish "technical batch effect" from "genuine condition-driven expression shift" and will remove both, artificially forcing conditions to mix.
- **Symptom:** Post-integration UMAP shows perfect mixing of condition and control cells even for a phenotype with strong prior evidence of a real transcriptional shift; pre-integration cluster proportions differed sharply by condition, but post-integration proportions look suspiciously uniform; known condition-responsive genes lose their differential signal after integration.
- **Fix:** Before integrating, check whether the correction variable is confounded with the biology of interest (contingency table of sample x condition x batch). If confounded by design, do not blindly integrate; instead flag the confound as a study-design limitation. Always keep an unintegrated/uncorrected assay or layer for expression-level statistical testing (integration embeddings are for clustering/visualization, not as direct DE input), and compare before/after integration UMAPs split by both cluster and condition to check whether real separation was erased.

## 11. Low cell-number clusters annotated with high confidence

- **Trigger:** A cluster with very few cells (e.g., <20-30 cells, or a tiny fraction of one sample) is given a specific, confident cell type label and used in downstream quantitative comparisons (composition, pseudobulk DE).
- **Mechanism:** Small clusters have unstable marker statistics (few cells means noisy average expression and unreliable p-values), are more likely to represent a clustering artifact, doublet cluster, or single-sample-driven island rather than a robust population, and pseudobulk aggregates from very few cells per sample behave like single-replicate measurements.
- **Symptom:** A cluster is almost entirely derived from one sample; marker significance for the cluster disappears when excluding the top few contributing cells; composition-based statistics for the cluster have implausibly large variance or undefined confidence intervals.
- **Fix:** Report cluster size and per-sample contribution alongside every annotation. Treat clusters with very low absolute cell counts or that are dominated by a single sample as low-confidence/exploratory; do not include them in headline pseudobulk DE claims without explicitly caveating the low replicate depth. Consider merging with a neighboring cluster or flagging as `needs_annotation` if marker evidence is unstable.

## 12. Cell type composition ("proportion") differences tested without accounting for compositional non-independence

- **Trigger:** Reporting that "cell type X is significantly increased in condition B" based on the raw proportion of cells per sample, using a naive per-cell test (e.g., chi-square across pooled cells) instead of a per-sample compositional test.
- **Mechanism:** Cell type proportions are compositional (they sum to 1 per sample), so an increase in one population mechanically decreases the apparent proportion of every other population even if their absolute abundance didn't change. Testing at the cell level again introduces pseudoreplication (see #2): thousands of correlated cells per sample are treated as independent trials.
- **Symptom:** Several unrelated cell types are all reported as "significantly changed" in the same direction opposite to one specific expanding population; proportion shifts don't hold up when tested at the sample level with a small number of samples.
- **Fix:** Compute proportions per biological sample, then test across condition using a method aware of compositionality and small sample size (e.g., scCODA, propeller, or a simple paired/unpaired test on arcsine/logit-transformed per-sample proportions with sample as the unit of replication). Report the number of biological replicates per condition alongside any composition claim.

## 13. Species/genome or gene symbol mismatches silently dropping genes

- **Trigger:** Combining datasets processed against different reference annotations (e.g., different Ensembl/GENCODE versions, or human vs mouse orthologs) or matching marker gene lists by symbol without checking case sensitivity or alias conflicts (e.g., mouse `Cd3e` vs human `CD3E`).
- **Mechanism:** Gene symbol matching is fragile: aliases, deprecated symbols, and case conventions differ across species and annotation versions, causing silent gene drops during merges, `FindVariableFeatures` intersections, or marker set matching, without an explicit error.
- **Symptom:** Fewer genes in a merged/integrated object than expected from either input; a well-known marker gene "missing" from the object that clearly should be there; module score based on a curated list scores as near-zero everywhere because most genes silently failed to match.
- **Fix:** Explicitly report gene overlap counts before and after any merge/intersection step. For cross-species work, convert via a maintained ortholog mapping rather than case-folding symbols. Check for missing expected genes as a QC step before interpreting module scores or marker results as biologically meaningful absences.

## 14. Treating module/gene-signature scores as absolute or comparable across independent runs

- **Trigger:** Comparing `AddModuleScore`/`score_genes` values across two separately processed objects, or interpreting a score's raw magnitude as a biologically meaningful absolute unit ("this pathway is 2x more active").
- **Mechanism:** Module scoring methods compute an expression average relative to a background gene control set drawn from the same dataset's expression bins; the background/control set composition depends on the specific object's gene expression distribution. Scores are therefore relative to the dataset they were computed in and are not directly comparable in magnitude across different objects, normalizations, or even different random seeds for the control gene sampling.
- **Symptom:** Absolute module score values are used to declare cross-study or cross-batch differences without accounting for the control gene set; small changes in gene list order or set size shift scores noticeably run to run.
- **Fix:** Compute and compare module scores only within the same object/normalization run, using consistent parameters, and treat cross-dataset comparisons as qualitative at best (or re-derive scores using a harmonized approach/reference). Report the gene set source, size, and scoring method/parameters in methods.
